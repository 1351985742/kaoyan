## 13:46 追到真根因：项目级技能目录是 `.codebuddy/skills`（推翻前两条结论）

**触发**：用户问「现在有了吗」。实测仍 `Can not find skill`，遂反编译 `codebuddy.js` 定位。

**关键事实**：
1. `AppStartup.log` 显示 13:44:03 `AppShutdown` → 13:44:09 `AppStartup source=app_startup`，`startup_type=cold`。**应用确实冷启动过**，但 13:44:16 `SessionSwitch` 恢复了同一个 session `928e2398`，**没有重新解析配置** → 仍找不到。所以「重启就好」被证伪。`last-launch.json` 每次交互都会刷新，不能当启动标记用。
2. `SessionRuntimeConfigResolver.resolveConfig` 今天只在 13:37:36 / 13:38:13 / 13:40:30 各跑一次，分别对应三个 sessionId。**技能清单随新建会话解析一次并缓存**（`productManager.waitConfiguration()`）。冷启动恢复旧会话 = 复用旧配置。
3. PathUtils 反编译结果：项目级技能目录 = `join(getWorkDir(), ".codebuddy", "skills")`，**硬编码 `.codebuddy`**。家目录 = `CODEBUDDY_CONFIG_DIR || ~/.codebuddy`，WorkBuddy 用环境变量指向 `~/.workbuddy`。故用户级 `~/.workbuddy/skills/` 有效、项目级要用 `.codebuddy/skills`。`replaceBrandName()` 只改正文文本里的 `.codebuddy`，不改路径字面量。
4. **推翻旧结论「扫描器不跟随软链」**：`isDirectoryEntry`/`isFileEntry` 对 `isSymbolicLink()` 为真时会继续 `stat()` 判断目标类型 —— 软链是被跟随的。

**处置**：`mkdir -p .codebuddy/skills` + `ln -s ../../.workbuddy/skills/kaoyan-math-coach .codebuddy/skills/kaoyan-math-coach`（相对软链，已验可解析）。未删改任何既有文件；`.workbuddy/skills/` 实体保留，等于两条路径名都覆盖。
