# 考研数学路径复习

帮助学生重新调用已有解题能力。统一覆盖约定范围内的路径，先独立提取，再集中评价；多数题允许回顾，用必要的实际推演检验中间处理和完整执行。本 skill 自含选题、评价、修复与记录规则，可单独调用。

## 固定原则

- **沿用现有分类。** 读取题库原有路径及用户已确认的层级；已确认的上位结构优先于较细的文件题型标题，不把其表现分支各算一条路径。不擅自重新聚类、合并、拆分或改写源文件。只有确实无法定位时才问一个定位问题。
- **从已分路径的文件起步。** “从头开始、按文件顺序”指在已有路径分组的文件集合中按目录及文件顺序推进。先检查实际路径标题或既有重排结构；跳过未分路径的原始题目文件，不把整个原始文件临时充当路径。同源原版与重排版只选一个含有效路径结构的版本，优先明确的路径重排版，不重复计覆盖；总览用于定位，不当作题目路径。发现误发时保留更正日志，从正式覆盖及当前待办中排除误发条目。
- **覆盖全部路径。** 评价决定修复深度和验证量，不作为跳过整条路径的筛选。每次只聚焦一条路径，组内连续完成、一次提交、集中反馈。
- **先题后讲。** 作答前不给启动卡、识别信号、方法标签、关键操作、变式解释、旧错提醒或解析。
- **不要求背诵。** 接受草稿、口语和不完整尝试，不要求每题复述标准路径图。题目回顾不等于完整手算；多数题只需展示实际回忆出的判断和推进过程。
- **以关键计算路径的可预测性判断回顾。** 学生能口头说明如何从条件推进到目标，包含决定结果的关键中间处理、必要条件及衔接，即可认定本题思路回顾通过，不要求算出最终数值。没有手算只表示实际计算执行未验证，不得当成回顾不通过，也不默认产生补算待办。只报方法名而无法判断关键衔接时如实记录证据范围；不要求逐题机械复述细节。
- **理解简洁表达。** 结合题目判断口述的自然含义：学生指出某个特征点且该题该点为何特殊是直接、唯一明显的原因时，可认定其识别了相应处理，不要求重复念出显然的公式；记录原话，并区分识别了特殊结构与已展示后续详细计算。含义确实存在多种合理解释时，不虚构细节。
- **逐题标记。** 每组集中反馈时，对每道已回应题分别记录路径标记和关键中间处理标记，按 [references/ledger.md](references/ledger.md) 写入台账。关键中间处理重点指相对通用解题场景不常见、常规套路可能漏掉的具体操作或衔接；它还须对结果或路径有实质影响。根据结构与用户实际证据判断，不因重要或未展示就把常规步骤标为关键；无须单列的题直接注明，不强造片段。依据学生实际表达，不以是否算出数值作为标准。未作答或跳过单独记录，无需为标记增加额外交互。
- **分开评价证据。** 题型识别与方法选择、整体流程、中间处理、完整执行分别评价。描述顺畅不证明能执行；片段成功不证明整题衔接；同路径分组内成功不证明脱离分组后仍能识别。
- **不把缺证据写成不会。** 保留学生真实过程。未写出的步骤标记“待验证”；不编造耗时、信心、独立性、错误原因或掌握结论。
- **台账是固定收尾。** 顺利路径也记录；中断也保存。自动写入并回读核验，不等待“请记录”，不增加确认轮次。

## 本地来源与入口

以下路径均相对于仓库根目录（包含 `.kiro/` 的目录）。

- 题库：`Obsidian题库`。
- 讲义：`讲义`；优先分章文件，不重复读取全书。
- 旧复盘：`考研`，以及已建立的 Notion 复盘库。
- 台账默认目录：`考研/路径复习台账`。有已约定的位置时沿用，不能另起互相冲突的总账。
- 读取 [references/ledger.md](references/ledger.md) 获取台账格式、保存和恢复规则。首次执行先注册明确复习范围内的原路径，再推进；范围未知时可先注册当前文件，不能把它当作全库范围。
- 集中评价、具体片段修复和逐题复盘保存，读取本 skill 的 [references/feedback-and-records.md](references/feedback-and-records.md)。不自动加载其他数学教学 skill 或继承其启动卡、逐题长复盘、题数进度和方法网络流程。

## 执行流程

### 1. 后台准备，不提前讲解

读取台账，恢复当前路径、历史证据、未解决断点和未作答题。查看题库原路径下的题目及相关复盘；后台独立做通拟选题，核验题面、解析和条件。

选能覆盖该路径主要表现和必要变化的典型题，避免重复同构堆量。已有锚点、变式、同构身份供后台选题用，作答前隐藏会泄露解法的标记。不固定每条路径相同题数，不因为旧错多就遗漏无错题记录的路径。

按已确认的上位路径一次整理题库记录，识别完全重复题、已有作答和尚未回顾的必要变化，再组成一批非重复代表题。保留题库全量与选题映射，便于快速推进；相关题归入同一结构是覆盖范围，不是学生已经做过或掌握的证据。未选题按需回访，不逐个文件标题重复运行一遍路径流程。

按 [references/intermediate-fragments.md](references/intermediate-fragments.md) 预标关键中间步骤，只作为候选验证点；不得预判为学生弱点。允许学生采用其他有效路线，不能强迫其复现参考解法。

出题前必须对每道入选题做一次中间处理判定，而非仅预标候选：后台做通关键转换，结合历史证据，决定“思路回顾”“写关键过程”或“完整作答”，并记录具体片段、理由和决定；没有值得落笔的片段也要记“思路回顾”及简短理由。按 [references/intermediate-fragments.md](references/intermediate-fragments.md) 执行，不等待学生先出错。实际风险、历史困难与任务结构相近时，主动选少量片段落笔；不按特殊函数或缺证据机械要求计算。

将每题的判定写入出题时的台账事件 `fragment_decisions`，与学生作答证据分开。对应题目在一次发齐的题组中标注中性要求，避免透露方法；待验证片段不可只存后台而不落实到作答要求或明确回访计划。学生改变有效路线时重新判定。无法完成判定时说明原因，不默认为已检查。

### 2. 一次呈现无提示题组

一条路径一次交付：完成后台选题后，将该路径本轮选定的全部题目一次发齐，学生统一回顾或作答后集中反馈；不先发代表题、再逐题续发常规变式。不跨路径打包，不一次铺开整个文件。完全重复题可以合并呈现，但列清合并的原题号和ID；没有选入的题保留后台理由。仅对实际反馈暴露的新断点安排必要补验，不将预先已知的常规题组伪装成临时追加。用户明确要求缩小或分批时，再调整当次呈现方式。

保留原题、选项、题号与来源，用中性标题编号。不原样展示含方法名或关键动作的路径标题、摘要、链接标签、工具提示、计时器分类和复制文本。原题本身提供的信息保留。

默认允许思路回顾，不强制整组完整计算。在少量需要执行证据的题上用“请写出关键推演过程”或“本题完整作答”等中性要求，不说明应当使用何种方法。回顾题无需另填路径卡；学生有纸笔困难时接受回顾，执行状态保留待验证。

随题组同时提供交互计时控制台：逐题状态、目标时间、启停/重置、单题和整组一键复制。目标时间是建议，未实际计时不能记成耗时；复制格式包含题号、用时和学生选择的作答方式，不泄露方法。Kiro 不支持在对话中内嵌交互控件，因此将计时器写成仓库根目录下的独立 HTML 文件（命名沿用现有 `*_timer.html`，参照已有计时页面的结构），并告知学生文件路径；页面标题和文本同样不得泄露方法。讨论工作流或编写 skill 时无需生成练习计时器。

出完题即等待集中反馈，不自行揭晓答案。用户临时只问一题的提示时，只给那题所需层级，不泄露未作答题；该题标注已获提示。

### 3. 一次集中评价

先评价学生真实过程，再给修正。稳定部分合并简述；错误、条件边界和重要省略步骤按需展开，不逐题套长篇模板或额外要求自评表。

四维分别说明现有证据：识别与方法、整体流程、中间处理、完整执行。答案正确但依据错误、猜对、记住旧答案、提示后完成、合法但较慢的路线分别处理。时间与独立性未知则保持未知。

按关键路径可预测性评价思路回顾，不以写出全部计算或最终数值为门槛。先前决定应落笔的片段，若学生已清楚口述关键处理及衔接，思路回顾可以通过；手算能力仅单独标未验证。确需检验执行时才依据风险、用户条件和效率安排片段或回访；用户不要求验证时遵从。Agent 可核验结果，但不能把自己的推演当成学生的口述或执行证据。

只有实际错误、明确犹豫、同类反复不稳，或确有高风险衔接时，才选少量片段补验并说明理由；“缺证据”本身不足以触发即时追问。必要补验集中安排，不将每个片段变成一次问答。用户觉得繁琐时立即收束当前回顾，保留证据局限并推进。新提示只能用于已提交部分，不能破坏其余题目的独立提取。学生已明确无从下手或请求直讲时直接帮助，标记相应证据条件。

### 4. 修复、收束、记录，再推进

局部问题针对片段处理；整体衔接有风险时保留必要完整作答。跨路径片段可以引用历史证据，但核对输入结构、成立条件、复杂度和是否独立完成，不从一次简单运算外推整类熟练。

以完成本轮复习为推进单位，不要求所有能力稳定后才能继续。反复受阻时记录未解事项并安排回访，避免无限补题。“本轮已复习”与验证程度分开，不能标成自动掌握。

每组结束时简短回顾该组解题路径，并结合台账指出实际暴露或需回访的关键处理；整体题目复习完成后，再结合台账进行整体路径回顾。

结束或中断时：按题目 ID 更新原复盘（有真实问题才新增）→ 自动更新路径台账 → 回读核验 → 简短报告保存结果、待处理项和下一位置。若写入失败，保留待保存内容并明确未成功；不能把失败当成功继续汇总。一次路径收束不自动创建方法网络卡、不改原刷题题数进度。

## 时间预算与记录边界

承接本次复习时，用户给定总预算为一周，每天可用时长尚未确认，不能编造每日配额。其他复习会话以当次预算为准，不永久套用一周。将明确的时间预算写进台账的范围说明或首条日志；按剩余时间、剩余路径和实际用时调整题量、完整手算比例、补验深度，所有延期、未覆盖与未验证项如实列出。

周内回访优先复发断点和缺少执行证据的关键片段。延迟检验未完成时保留待回测，不因到期就认定掌握。用户明确不记录时遵从，不偷偷保存相关学习内容。

逐题复盘继续复用现有数据库；路径台账保存覆盖、证据、待办及恢复位置，不复制整套题解、不另建错题库。不自行新建 Notion 数据库、扩充一堆属性或将每个中间步骤做成方法卡。外部写入不可用时，先保存本地待同步稿并如实记录同步状态。
