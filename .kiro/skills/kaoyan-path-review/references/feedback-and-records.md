# 集中评价、局部修复与原复盘衔接

本文件是路径复习自身的评价与记录规则，不需要加载其他数学教学 skill。共用题库、讲义和既有逐题复盘数据，不继承其他学习流程。

## 集中评价

先独立核验题目，再对照学生实际提交的过程。不能用参考解法补写学生未展示的过程。允许有效替代路线，区分错误、有效但成本偏高、路线合理但执行未完成和可靠完成。

路径复习的主要通过标准是**能否完整预测关键计算路径**：从题目条件到目标，知道采用何种方法、关键中间处理怎样做、必要条件和结果怎样衔接；口述、草稿或心算均可，最终数值和完整纸笔计算不是必需项。按实际证据判为“关键路径已预测”“入口正确但关键衔接不清”“关键处受阻”等，并简述依据；不强迫每题套模板或把泛泛的方法名自动认作完整预测。实际手算是否展示单独记录，未展示不等于回顾未通过或需要补算。必要时用一个简短追问辨别具体关键衔接，集中处理，尊重用户觉得简单、不需要验证或当前无纸笔的要求。

每道已回应题的台账须同时填写路径标记与中间处理标记，并区分能否预见和实际是否展示计算；用学生原话或实际过程说明具体判断。对未涉及的片段标记“未涉及”，不把 Agent 解释或题库错误算作学生表现；无需逐题额外追问。

| 主要断点 | 有证据时的判断 | 修复方式 |
| --- | --- | --- |
| 知识或条件 | 定义、定理条件、公式适用范围使用错误 | 补最小必要概念与边界，再回到原步骤 |
| 识别 | 提示后理解，但原题面未提取出信号 | 对照题面和第一操作，后续用未提示题验证 |
| 方法选择 | 有效路线明显增加当前题目的计算、分支或风险 | 比较本题路线成本，保留熟悉且有效的方法 |
| 中间处理与计算 | 路线成立，局部变形、变量、符号、约束或推演出错 | 展开具体片段，写清输入、处理与输出 |
| 时间控制 | 已无有效进展仍继续或进行了不必要推导 | 指出可观察的止损信号与备用动作 |

一个问题只选一个有依据的主要断点。更早的方法选择导致后续计算失控时，不能只归为计算错误。缺少过程只标缺证据；不凭一次表现归纳长期弱点。不用“粗心”代替具体机制。

集中反馈先概述本组已经展示的能力，再展开需要修复的少数问题，最后列待验证片段及后续动作。无需每题列出一套教学栏目。

## 具体片段修复

保留学生原写法和有效部分，展示出错位置及一套经济、合法的实际推演，再留一句可操作提醒。仅涉及计算困难时不额外生成知识网、路径卡或整题长解。

逻辑条件和信息保留属于中间处理，不能都化约为算术练习。对合法但较慢的方法，根据本题比较成本，不能宣称替代方法普遍更快。

学生明确只要提示时，仅给当前需要的一层；其他未作答题不揭晓。学生已说完全没有思路或请求直接讲解时可以直讲，记录“提示后/看过解答”，不声称独立完成。

## Notion 写入

1. 使用可用的连接工具读取数据库结构与原记录，不能假设字段仍与旧记录完全一致。
2. 复用现有 `掌握状态`、`二刷结果`、`错误类型`、`复发次数` 等字段；只设置确有证据的值。一次讲解后可记已纠偏，不记已掌握。实际延迟独立作答和必要变化未完成，保留待验证。
3. 计算帮助在实际已有 `题型分类` 中复用 `计算能力专题` 标签；字段不存在时不擅自改数据库结构，本地注明即可。
4. 数学公式用原生 `equation` 块或 inline equation rich text。不要将 `$...$`、`\(...\)`、`\[...\]` 当普通文本写入页面。
5. 写后重新读取，核验目标题目、原有内容、公式和本次更新确已保存。未回读成功不能记 Notion 已核验。

不编造耗时、信心、二刷结果或复发次数；复发只能来自后续真实作答。首次独立成功与提示后成功分开记录，路径复习状态不映射成逐题已掌握。

连接不可用、权限不足或外部写入失败时，将本次原题定位、原始反馈和拟更新内容写入台账目录的 `pending/`，按题目 ID 与日志 ID 命名，链接到对应路径日志并记 `待同步`。本地保存成功与 Notion 同步成功分别报告；不为同步另建数据库。

用户明确不记录时遵从。路径台账自身按 `ledger.md` 保存；不依靠逐题复盘数量推算路径覆盖，不更新原刷题题数进度或方法网络。
