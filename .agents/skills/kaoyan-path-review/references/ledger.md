# 路径复习台账

## 存储与身份

默认目录 `考研/路径复习台账`，相对于教材工作区；工具参数使用绝对路径以避免工作目录变化。

- `ledger.json`：主数据，一条路径一条记录，追加各次复习日志。
- `台账.md`：由主数据生成的可读总览与日志。恢复时主数据为准；手写学习解释放在原复盘，不编辑派生总览。

使用 `scripts/ledger.py`，仅依赖 Python 标准库。它注册路径、追加日志、生成总览并回读确认，不负责数学诊断或猜测学生状态。不要用它生成虚构复习结果。

路径身份为原题库相对文件名＋从根到该路径的完整原始标题序列（`heading_path`）。例如不同文件的 P1 不会混淆。同名标题在同一文件中仍有歧义时，先明确原有定位，不自动重分路径。

首次从已确认复习范围提取原路径注册；记录范围文字 `scope_note`。只注册当前文件时总数仅代表当前文件，不能声称整个题库已登记。源标题改名或文件移动后，不重置旧历史；先核实映射，明确迁移再操作。

## 命令

以下 `SKILL` 和 `LEDGER` 为说明中的路径，不是要求重设系统环境变量。实际调用填写绝对路径。

```text
python3 SKILL/scripts/ledger.py register --root LEDGER --input /tmp/review-register.json
python3 SKILL/scripts/ledger.py record --root LEDGER --input /tmp/review-session.json
python3 SKILL/scripts/ledger.py show --root LEDGER
python3 SKILL/scripts/ledger.py show --root LEDGER --path-id ID
```

准备 register 输入时先读源文件；可用同脚本 `headings --file ABSOLUTE_BANK_FILE` 列出原始标题序列，供定位用。它列出所有标题，不替 Agent 判断哪些是现有路径，禁止将题号或锚点/变式层级误注册成独立路径。

注册输入：

```json
{
  "bank_root": "/Users/devilrecal/Downloads/教材/Obsidian题库",
  "scope_note": "填写已确认的实际复习范围",
  "paths": [
    {"source_file": "相对于题库的原文件.md", "heading_path": ["原一级标题", "原路径标题"]}
  ]
}
```

上例是格式说明，不能直接注册。脚本验证源文件和标题存在、定位唯一，重复注册保留历史。后续补注册不得更换题库根目录或悄悄覆盖原范围描述。

追加日志输入：

```json
{
  "path_id": "注册命令返回的ID",
  "session_id": "本次日志的唯一编号",
  "date": "用户当地日期，YYYY-MM-DD",
  "status": "进行中",
  "questions": [
    {"question_id": "原题ID或原题号", "mode": "思路回顾", "independence": "未说明", "evidence": "实际收到的过程摘要或可访问的证据链接"}
  ],
  "assessment": {
    "题型识别与方法选择": "有描述证据；写明依据与局限",
    "整体流程": "按实际表现填写",
    "中间处理": "未验证",
    "完整执行": "未验证"
  },
  "fragments": [],
  "followups": ["有依据的待验证、待修复或回测事项"],
  "next_action": "实际恢复位置或下一动作",
  "problem_records": [],
  "notion_sync": "未使用"
}
```

只有已发生的结果才填。`status` 取 `进行中` 或 `本轮已复习`；这是本轮流程状态，不是掌握状态。注册后无日志为 `未开始`。四维判断用实际文字表达，不强制打分。

`assessment` 中的“整体流程”“中间处理”明确记录学生是否已经预测出从条件到目标的关键路径与衔接，结合原话区分已预测、部分预测、受阻或证据不足；可把已清楚口述的完整关键路径评为思路回顾通过，无须最终答案。`完整执行` 仅记录实际计算是否展示，不应反过来否定路径回顾通过；不因未手算自动生成待办。不编造学生未说的衔接，允许简洁有效的口述，不强制逐步复述。

`mode` 取 `思路回顾`、`片段手算`、`完整作答`。`independence` 取 `独立`、`提示后`、`看过解答`、`未说明`。一题有多种活动可分别记录。可加入实际耗时等字段，但不填推测值。

集中反馈事件中，每道已回应题在 `questions` 条目增加 `review_mark` 和 `mark_reason`，逐题标记本轮路径表现与证据：如“路径已预测”“主要路径清楚”“需纠偏”“方向待确认”“受阻”等，词语须匹配实际口述和不确定度；不将未写答案当作未通过。未回应的题不虚构评价。历史日志缺此字段时保留原样，用户要求时按原话追加补记，不能把后来讲解当成当时独立表现。

每道已回应题还需填写 `calculation_mark` 和 `calculation_reason`，针对本题实际关键中间处理逐题标记：`处理能预见`（能说清关键处理）、`处理有疑惑`（学生对具体处理表达犹豫）、`处理受阻`（明确不会或无法继续）、`处理有误`（已展示具体错误）、`未涉及`（未谈到具体处理，不能推断能力）。写明针对的处理及学生证据；口述仅涉及方向而具体处理未说明时记“未涉及”，不能把证据不足写成学生犹豫。另以 `calculation_executed` 标记 `已展示`、`未展示` 或 `未说明`，记录实际计算是否展示，与能否预见互不替代。未作答题不虚构评价；出题事件和旧日志没有这些字段也合法。无需为了填写标记要求追加计算或提问。

只选择相对通用解题流程不常见且会影响结果或后续推理的关键中间转换，说明题目情境、与常规做法的不同和可能后果；常规处理即使影响结果，也不因此自动列为关键。用户明确不熟的常规操作可以个人薄弱项记录，注明实际证据和与非常规片段的区别。普通计算或“分类讨论”“求导”“判断连续”等路径层动作本身不能充当关键处理。题目无需要单列的关键片段时 `calculation_mark` 填 `无须单列`、说明理由，不人为制造问题。学生只说了总体路径时，对确有必要单列的具体片段记“未涉及”，不由此推断不会或自动安排补算。

识别学生简洁表达的自然数学含义，结合题目判断：明确指出有明显特殊结构的点，且结构原因直接唯一时，可记为已识别该结构，不因为未逐字重复原因就记未涉及；保留原话与推断依据，不外推已完成具体计算。存在多种合理解释时标记不确定，不编造学生思路。

每个片段至少保留：`fragment_id`、`question_id`、`input_context`、`conditions`、`task_kind`（识别与选择/执行）、`result`、`evidence`。需要时补充输出状态、提示条件、复用证据来源及适用局限。回顾未涉及片段时可以为空，但不得声称片段验证已完成。

出题事件的 `fragment_decisions` 逐题记录后台判断：`question_id`、`decision`（思路回顾/写关键过程/完整作答）、`fragment`、`rationale`、`evidence_basis`、`followup`。这是计划，不是学生作答或掌握证据；实际执行另记在后续 `questions` / `fragments`。判断要在发题前写入并回读，后续改变决策保留原因；历史事件无此字段不需倒填。

`problem_records` 放原复盘链接或本地待同步稿路径，不复制完整解答。`notion_sync` 取 `未使用`、`待同步`、`已核验`；后者必须由真实外部回读支持，本地脚本成功不证明 Notion 成功。

## 自动保存与恢复

1. 题目出现真实断点时，按 ID 更新原复盘；正确但猜测、低效或提示依赖也可更新。稳定通过只留台账证据，不制造错误记录。
2. 收束时提交一次日志，包括无错路径；中断时先保存进行中。追加回测日志保留旧结果，不覆盖历史。
3. `session_id` 标识一次保存事件：相同输入重复提交是幂等重试；同 ID 不同内容会拒绝，后续反馈使用新日志 ID，不覆盖已保存结果。
4. 脚本原子替换主数据并回读核验，再重建 Markdown 总览。单写入者顺序执行，不并行改同一台账。总览写入失败时说明主数据是否已保存，用相同输入重试可重建。
5. 简短报告真实保存结果和未完成事项。写入失败不能标“已记录”；保留输入供重试。
6. 下次读取当前记录、历史片段、待办和未作答题。新日志明确哪些旧待办已解决、仍保留哪些；最新待办是当前工作集合，不能无故清空。

总览按注册范围显示未开始、进行中、本轮已复习数量，并另列待办；不能把已复习路径数当题数，不能写入旧题数进度，也不能把本轮已复习等同掌握。本台账不触发方法网络维护。

## 外部记录衔接

现有复盘库位置、逐题更新和 Notion 原生公式、查重、回读规则见本 skill 的 [feedback-and-records.md](feedback-and-records.md)。当前连接不可用时本地保存待同步稿并记录实际同步状态，不声称已写入 Notion。未经用户要求不建立新的外部台账数据库或修改原数据库结构。
